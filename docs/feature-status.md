# 実装済み機能一覧（2026-07-27時点）

現時点でコードベースに実装済みの機能を、公開側・人材アカウント・企業アカウント・管理者・インフラの5つに分けて整理する。

## 公開側（誰でもアクセス可）

- ホーム（`/`）: サービス紹介、検索フォーム、注目人材3名のカード表示（`src/data/talents.json`のモックデータのまま、実データ未接続）
- 人材一覧（`/talents`）: 分野・JLPTレベル・居住地での絞り込み、名前/スキル検索
- 人材詳細（`/talent/:id`）
- お問い合わせフォーム（`/contact`）: 氏名・会社名・メール・種別・本文を送信 → `inquiries`テーブルに保存（管理者のみ閲覧可）
- EN / JA / FR の3言語切り替え（UIは主にEN/JA中心）

### 企業アカウント限定ゲーティング（NEW）

人材一覧・詳細ページは実際のSupabaseデータ（承認済みプロフィールのみ）を参照するようになった。

| 閲覧者 | 見える範囲 |
|---|---|
| 企業アカウント（ログイン済み） | 氏名・自己紹介・職務経歴・連絡先を含む全項目 |
| 管理者 | 同上（全件・全ステータス閲覧可） |
| 未ログイン／人材アカウント | 分野・国・スキル・JLPTレベル・大学・就業可能時期など安全な項目のみ。氏名・写真・自己紹介はぼかし表示＋「企業アカウントでログイン」CTA |

- DBのRow Level Securityで実データ自体を制限（フロントでの見た目だけの隠蔽ではない）
- 未ログイン向けの安全な項目は`profiles_preview`ビュー経由で取得

## 人材アカウント（role: talent）

- メール/パスワードでサインアップ・ログイン
- ダッシュボード（`/dashboard`）でプロフィール編集
  - 基本情報（氏名EN/JA、ヘッドライン、就業可能時期、JLPTレベル、求職中フラグ）
  - 学歴（大学・学部、EN/JA）
  - スキル（EN/JA、カンマ区切り）
  - 自己紹介（EN/JA）
  - 語学スキル（複数追加・削除可）
  - 職務経歴（複数追加・削除可、会社名・役職・期間・業務内容をEN/JAで）
- プロフィールステータス: `draft → pending → approved/rejected`（`approved`のみ公開一覧に表示）

### 既知の未接続部分
- `submitForReview()`（下書き→審査申請）はAuthContext・i18n文言とも用意済みだが、ダッシュボードにボタンが未配置。現状だと申請済みにならないため、admin側のPendingキューに出てこない可能性が高い。

## 企業アカウント（role: company）（NEW）

- ログイン画面で「人材として登録」「企業として登録」を切り替えてサインアップ可能。企業選択時は会社名の入力欄が表示される
- ログイン後は人材一覧（`/talents`）へ遷移し、全プロフィールを閲覧可能
- ナビバーに会社名＋ログアウトボタンを表示
- DB上は`companies`テーブル（会社名・説明・業種・規模・Webサイト・ロゴURL）が用意済みだが、企業側の自社プロフィール編集画面はまだ未実装（サインアップ直後は会社名以外は空欄のまま）

## 管理者（role: admin）

- `/admin`: 承認待ち（pending）一覧・全件一覧のタブ切り替え
- プロフィールの承認／却下（却下理由コメント付き）
- 問い合わせフォーム（`inquiries`）の内容を閲覧可能（管理者のみ）

## インフラ・DB

- Supabase（Postgres + Auth + RLS）バックエンド、マイグレーション6本
  - 初期スキーマ → プロフィール項目追加・承認フロー → RLS再帰修正・inquiries追加 → grants修正 → 企業ゲーティング（RLS強化・`profiles_preview`ビュー） → `handle_new_user()`のsearch_pathバグ修正
- Netlifyへのデプロイ設定（`public/_redirects`）は初期MVPのまま

## 次にやると効果が大きそうなこと

1. `submitForReview`をダッシュボードに配線し、承認フローを実際に機能させる
2. 企業アカウント向けの自社プロフィール編集画面（`companies`テーブルはDB上は用意済み）
3. 特定の人材への直接コンタクト（`contact_requests`テーブルはDB上はあるが未使用。現状の問い合わせは`inquiries`という汎用フォームのみ）
4. 承認・却下時の人材へのメール通知
