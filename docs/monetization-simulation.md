# マネタイズシミュレーション（フェーズ別損益分岐点）

[[monetization-options]]の段階的マネタイズ戦略（Phase 0〜3）について、どのくらいの取引量があれば黒字化のめどが立つかを試算する。数字は仮置きの前提に基づく一次シミュレーションであり、実態に応じて随時更新する。

## 前提条件（仮置き）

| 項目 | 仮定値 |
|---|---|
| Phase 2の成功報酬率 | 年収の25%（業界標準20-35%の中間、実績が薄いので保守的に設定） |
| 採用人材の平均年収 | 450万円 |
| ビザ・行政書士等の外注費（1件あたり） | 10万円 |
| Phase 0チーム | 1〜2名 |
| Phase 1チーム | 2〜3名 |
| Phase 2チーム | 4名（営業/BD、審査・マッチング、ビザ・生活サポート、システム保守） |
| Phase 3チーム | 8〜10名 |
| 1人あたり月間フルコスト | 50万円（給与+社保+間接費、初期は抑えめ想定） |

## フェーズ別損益分岐点シミュレーション

### Phase 0（0〜8社、最大6ヶ月）— [[phase0-non-monetary-exchange]]参照
- 収益: ¥0（意図的に無償。対価は事例・フィードバック・LOIなどの非金銭資産）
- 人件費: 月80〜120万円（1〜2名+ツール+ビザ外注の一部負担）
- システム運用費: 月0〜5,000円（無料枠でほぼ十分）
- **累計必要投資額（ランウェイ）: 約480〜720万円（6ヶ月分）**
- 位置づけ: 損益分岐点ではなく「証拠を作るために必要な運転資金」として捉える

### Phase 1（低コミット課金：コンタクト解放/軽量サブスク、ARPU 3〜5万円/社・月）
- 人件費: 月100〜150万円（2〜3名）
- システム運用費: 月2〜5万円（動画ホスティング、LLM API試験運用を含む）
- 損益分岐点: **月20〜30社の有料契約が必要**
- 位置づけ: この水準は初期トラクション段階では非現実的。**黒字化が目的ではなく「企業がお金を払うことへの抵抗感を確認する検証フェーズ」**とする

### Phase 2（成功報酬モデル、本命フェーズ）
- 1件あたり粗利: 112.5万円（成功報酬）− 10万円（外注費）= 約102.5万円
- 人件費: 月200万円（4名）
- システム運用費: 月15〜30万円（AIセマンティックマッチング、AI面接コーチ、ビザチャットボットの本番運用を含む）
- 月間固定費合計: 約215〜230万円
- **損益分岐点: 月2〜3件の成約（年24〜36件）**
- 営業利益100万円/月を狙うなら: 月3件強の成約が必要
- **ここが最初の現実的な"めど"。月2〜3件の成約を安定して出せるかどうかが事業の生死を分ける**

### Phase 3（スケール、成功報酬＋継続SaaS/EOR）
- 月10件成約（1,025万円）+ EOR/SaaS課金50社×2万円（100万円）= 月間売上ライン1,125万円
- 人件費: 月500万円（8〜10名）
- システム運用費: 月50〜100万円（AI機能の利用量次第で変動大、目安は売上の5〜15%）
- **営業利益: 月400〜550万円程度**

## 2人体制シナリオ（最初はこの体制で回す想定）

Phase 2の成功報酬モデルを、当初想定の4名体制ではなく2人体制で回した場合の再計算。

### 固定費

| ケース | 人件費 | システム運用費 | 月間固定費合計 |
|---|---|---|---|
| ベースケース（市場給与） | 2名×50万円=100万円 | 約10万円 | **110万円/月** |
| リーンケース（創業者が給与を抑える、例:25万円×2名） | 50万円 | 約10万円 | **60万円/月** |

### 損益分岐点

1件あたり粗利102.5万円（成功報酬112.5万円−外注費10万円）で計算:

| ケース | 月間損益分岐点 | 年間 |
|---|---|---|
| ベースケース | 110万円 ÷ 102.5万円 ≈ **月1.1件** | 約13件/年 |
| リーンケース | 60万円 ÷ 102.5万円 ≈ **月0.6件** | 約7件/年 |

4人体制（月2〜3件必要）より大幅にハードルが下がる。2人体制なら「月1件、年10〜13件」が黒字化の現実的なめど。創業者が初期の給与を抑えられれば、年7件（2ヶ月に1件ペース）でも黒字化ラインに乗る。

### 必要なパイプライン規模（人材・企業）

成約1件を生むための歩留まりを仮に「契約企業の40%が採用に至る」とすると:

- **企業側**: 月1件成約のためには常時**5〜8社程度のアクティブな商談パイプライン**が必要
- **人材側**: 1採用あたり平均3〜5名の候補者との接点が必要なため、常時**15〜20名程度のアクティブな人材プール**を維持するのが目安

企業5〜8社・人材15〜20名という規模は、[[phase0-non-monetary-exchange]]で設定した「Phase 0の上限8社」というキャパシティ感ともほぼ一致しており、2人体制の運用限界と整合する。

## 業務委託シナリオ（正規雇用の代替案）

これまでの試算はすべて「正規雇用＋成功報酬（一括受取）」が前提。業務委託（Andela型のマークアップ/haken型）に変えた場合の経済性を試算する。

### 経済性

- クライアント企業への請求額（月額）: 例）月40万円（リモート契約エンジニアとして妥当な水準）
- 人材への支払い（月額）: 例）月20万円（アフリカ在住者にとっては十分魅力的な水準）
- **マークアップ（粗利）: 月20万円/契約**（継続的に積み上がる）

正規雇用の成功報酬（102.5万円を一括で1回）と異なり、1件の契約が毎月20万円を生み続ける。1年間では1契約あたり240万円となり総額では正規雇用モデルを上回るが、月々の入金は分割されるため損益分岐点の考え方が変わる。

### 損益分岐点（2人体制、必要な同時進行契約数）

固定費を月次マークアップで割ると、必要な"同時進行契約数"（ストックベース）が出る:

| ケース | 月間固定費 | 必要な同時進行契約数 |
|---|---|---|
| ベースケース | 110万円 | 110万円 ÷ 20万円 = **5.5件（常時同時進行）** |
| リーンケース | 60万円 | 60万円 ÷ 20万円 = **3件（常時同時進行）** |

正規雇用モデルは「月1件成約すれば黒字」という**フロー（新規獲得数）ベース**の指標だったが、業務委託モデルは「常時3〜6件が稼働している状態を維持する」という**ストック（累積契約数）ベース**の指標に変わる。立ち上がりは時間がかかるが、到達後は解約が同時多発しない限り収益が安定する。

### 最大のインパクト：ビザ問題の回避

業務委託でリモート契約にすれば、人材は日本に来る必要がなくアフリカに居住したまま働けるため、[[scope-japan-resident-vs-overseas]]で懸念していたCOE（在留資格認定証明書交付申請）の重さや在日人材プールの枯渇問題が回避できる。対象人材プールが一気にアフリカ全域に広がる。

### 注意点

- **偽装請負リスク** — 実態が労働者派遣に近いと労働者派遣法上の問題になりうる。契約設計（成果物ベースの委任・請負であることの担保）が必須
- **越境決済・為替リスク** — 円で受け取りアフリカの通貨で支払う場合の為替変動、送金コスト、税務（源泉徴収等）の実務対応が必要
- **リモート向きの職種に限定される** — ITエンジニア等とは相性が良いが、対面が必須の職種には使えない

## システム運用費の内訳（フェーズ別詳細）

| フェーズ | 主な費目 | 月額目安 |
|---|---|---|
| Phase 0 | Netlify無料枠、Supabase/Firebase無料枠、ドメイン | 0〜5,000円 |
| Phase 1 | Supabase Proプラン、Netlify有料化、動画ホスティング、LLM API試験運用 | 2〜5万円 |
| Phase 2 | DBスケール対応、動画ストリーミング、LLM API本番運用、経歴検証サービス、セキュリティ/バックアップ | 15〜30万円 |
| Phase 3 | 利用量に比例して増加 | 50〜100万円 |

**最大の変動要因はAI機能（セマンティックマッチング、AI面接シミュレーション、ビザチャットボット）のLLM API利用料。** 候補者数×利用頻度に比例してコストが積み上がるため、機能のリッチさとコストのバランスを機能設計時に意識する必要がある。

## 主要な気づき

- Phase 1に黒字化を期待するのは無理筋。ここで課金モデルを強化しようとすると事業として無理が出る。Phase 1は検証専用と割り切るのが良い
- 本当の"めど"はPhase 2の月2〜3件成約。これが最初の具体的なマイルストーン（採用予定人数・営業活動量に落とし込める数字）
- システム運用費はPhase 0〜1ではほぼ誤差の範囲。Phase 2で人件費に対して数%〜15%程度のインパクトを持ち始める
- 成功報酬率・平均年収・チーム人数・AI機能の利用量を変えると損益分岐点は大きく動くため、実態に近い数字が判明次第、随時更新する

## 未決定事項

- AI機能をどこまでリッチにするか（Phase 2以降のシステム運用費を左右する最大変数）
- 実際の採用予定年収レンジ（成功報酬額の前提に直結）
